Where Things Go Wrong

Across 172 sessions you got a lot shipped, but friction clustered around visual details Claude missed on the first pass, scope that ballooned beyond what you asked for, and environment/registry gotchas that sent debugging down the wrong path.

Pixel-level UI details requiring multiple correction rounds
Your UI work consistently needed you to point out alignment, border, and spacing details that Claude declared "verified" but hadn't actually checked. You could shorten these loops by stating the acceptance criteria up front — e.g. "match the reference within 1px, keep all existing borders, no vertical shift between tabs" — so Claude measures against them instead of eyeballing.
  • The Apollo-style settings layout took several rounds where you had to flag a missing border-bottom, a title aligned to tab text instead of button edge, underline extent, and canvas color one at a time
  • The tab variant swap shipped with a 1px misaligned underline, and the contacts Data tab redesign introduced a 6px vertical shift between Overview and Data that you had to catch
Over-building beyond the requested scope
Claude repeatedly delivered more than you asked for, which then had to be stripped back out — costing more time than the original task. Explicitly bounding the work ("flat catalog only, no templates, no archive") before Claude starts would prevent these rewrites.
  • For the requirement catalog you wanted a single flat list, but Claude built a multi-template library with duplicate/archive/default badges and two editor pages, forcing a full rewrite of schema, migration, routes, UI, tests, and docs
  • The kanban card redesign came bundled with a large unrequested soft-delete feature; separately, a misread padding complaint triggered a whole layout-bleed refactor that had to be reverted
Environment and registry gotchas that misdirect debugging
A recurring pattern: a route or config isn't registered somewhere, or the dev environment is stale, and Claude spends the session chasing the wrong cause. Telling Claude to check route registries and restart/verify the dev server before investigating layout or interaction bugs would cut these detours.
  • A stale/crashed Vite dev server plus offset screenshot click coordinates caused a long false-alarm investigation into "sheets not opening" that was never a real regression
  • New routes (the Activity tab, the admin user-detail page) weren't added to the app-shell route-id registry, so they rendered with wrong padding and width until you pointed it out; a pending 0044_groups migration also 500'd and blocked browser verification entirely
